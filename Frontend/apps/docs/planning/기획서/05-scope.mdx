# 5. Out of Scope — MVP 제외 기능

아래 기능은 MVP(1차 출시)에 포함하지 않는다. 명시적으로 제외함으로써 범위 확장(scope creep)을 방지하고, 팀이 핵심 가치(사주 기반 소개팅)에 집중할 수 있도록 한다.

| 기능 | 제외 이유 | 검토 시점 |
|------|---------|---------|
| 오행 기반 위치·장소 추천 | 위치 권한 수집 및 Kakao Local API 연동이 필요하고, 소개팅 서비스의 핵심 가치(사람 연결)와 직접 연결되지 않는다. 사주 정보 활용은 매칭 알고리즘에 집중한다. | 미검토 (방향 불일치) |
| 결제 기반 궁합 잠금 해제 | 사주·궁합 정보는 무료로 제공한다. 수익은 소개팅 참가권·좋아요 충전에서 발생하며, 정보 접근에 결제 장벽을 두면 온보딩 이탈이 급증한다. | 영구 제외 |
| 커뮤니티 피드 (게시글·댓글) | 콘텐츠 모더레이션·신고 시스템·피드 알고리즘이 필요하다. MVP 핵심인 소개팅 연결과 직접 연결되지 않으며, 사용자 기반이 충분히 형성된 후 검토한다. | 3단계 |
| 포인트·충전 시스템 (좋아요 충전 포함) | 1:1 소개팅 좋아요 충전은 3단계 기능으로 분류한다. 포인트 회계·소진 정책·환불 로직이 복잡해 초기 도입은 과도하다. MVP~2단계는 로테이션 소개팅 참가권 단건 결제에만 집중한다. | 3단계 |
| 다수 인물 동시 등록 (3인+) | MVP는 '나 + 매칭 상대' 구조. 가족·친구 사주 관리는 소개팅 서비스 방향과 맞지 않는다. | 미검토 |
| SNS 공유 (즉시) | 오픈그래프 이미지 생성 서버가 필요하다. 출시 후 바이럴 데이터를 확인하고 우선순위를 결정한다. | Nice to Have로 이월 |
| 네이버·구글 소셜 로그인 | 카카오 로그인만으로 국내 타겟 90%+ 커버. 추가 provider는 스키마 변경 없이 가능하나 MVP 우선순위에서 제외. | 2단계 |
| 결제 구독(정기 결제) 모델 | 단건 결제(참가권·좋아요 충전) 전환율 검증 전에 구독 모델은 시기상조. PG사 정기 결제 계약도 별도로 필요하다. | 3단계 |
| AI 기반 이미지 생성 (프로필 카드) | 이미지 생성 API 비용·속도 최적화가 필요하다. MVP 핵심 기능 완성 후 마케팅 차원에서 검토한다. | 출시 후 결정 |
| 다국어 지원 | 국내 MVP 검증 우선. i18n·번역 리소스·해외 역학 데이터 검증이 필요하다. | 3단계 |
