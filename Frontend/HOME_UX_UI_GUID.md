# HOME UX/UI Guide

## 1) 목적

`/` HOME 화면을 만들 때, 레퍼런스 사이트(`https://www.jeomsin.co.kr/`)의 정보 구조/배치를 최대한 동일하게 가져오되,  
우리 프로젝트의 현재 디자인 컨셉(Notion 같은 핸드드로우 sketch)을 유지하기 위한 구현 기준 문서.

## 2) 고정 원칙

- 구조/배치: 점신 홈의 섹션 순서와 정보 위계를 우선 복제한다.
- 스타일/톤: 현재 프로젝트의 sketch 토큰/컴포넌트를 유지한다.
- 레퍼런스가 모바일 중심 UI여도, 우리 HOME은 모바일 앱 프레임을 복제하지 않는다.
- 즉, **콘텐츠 구조/배치는 점신 기준**, **레이아웃 프레임은 데스크탑 웹서비스 템플릿 기준**, **비주얼 마감은 현재 프로젝트 기준**으로 작업한다.

## 3) HOME 레이아웃 명세 (점신 레퍼런스 기준)

아래 순서를 기본 뼈대로 사용한다.

1. 상단 헤더 영역  
2. 메인 배너(히어로) 영역  
3. 빠른 진입 메뉴(주요 서비스 카드/아이콘)  
4. 추천/프로모션 카드 영역(가로 스크롤 가능)  
5. 카테고리별 서비스 리스트 블록(섹션 반복)  
6. 하단 고정 네비게이션(모바일 우선)  

## 3-1) 레이아웃 프레임 규칙 (중요)

- 점신의 `단일 모바일 프레임` 레이아웃은 그대로 가져오지 않는다.
- 데스크탑 기준 기본 프레임:
  - 글로벌 헤더 + 메인 컨테이너(`page-shell`)
  - 메인 콘텐츠 다단(예: 메인 8~9 / 사이드 3~4) 또는 `page-grid` 기반
  - 필요 시 우측 보조 패널(추천, 배너, CTA) 배치
- 모바일에서는 단일 컬럼으로 축소하되, 데스크탑 정보 구조가 자연스럽게 접히는 형태로 구성한다.
- 따라서 구현 우선순위는 다음과 같다:
  1. 데스크탑 웹서비스 레이아웃 설계
  2. 그 안에 점신형 콘텐츠 섹션 순서/위계 이식
  3. 모바일 반응형 축소

## 4) 디자인 시스템 적용 규칙

- 필수 재사용:
  - `src/app/globals.css`의 sketch 계열 토큰/유틸 (`sketch-border`, `sketch-highlight`, `sketch-input`)
  - 공용 버튼/카드 패턴 (`btn-saju-*`, `card-saju-primary`, `hero-panel`)
- 유지해야 할 시각 언어:
  - 아이보리 배경 + 검은 보더 + 오프셋 그림자
  - 작은 라운드(`rounded-sm`) 위주
  - 과한 그라디언트, 네온 글로우, 유리질감 사용 금지

## 5) 콘텐츠/컴포넌트 변환 규칙

- 점신 구조를 참고하되 텍스트/카피/아이콘/데이터는 우리 서비스 맥락으로 치환한다.
- 기존 `WelcomSection`이 있는 경우:
  - 섹션 단위로 분해 가능한 블록(배너, 퀵메뉴, 추천, 리스트) 중심으로 재구성한다.
  - UI 컴포넌트는 props 기반 렌더링에 집중하고, 상태/조회 로직은 `features/*/hooks`로 분리한다.

## 6) 반응형 기준

- 모바일 우선: `320px ~ 480px`에서 정보 밀도/탭 접근성을 우선 보장한다.
- 태블릿/데스크탑: 메인 컬럼 폭을 제한하고 좌우 여백 또는 보조 패널을 추가한다.
- 모든 구간에서 텍스트 겹침/버튼 눌림 영역(최소 40px) 미달이 없어야 한다.

## 7) 접근성/품질 체크리스트

- 클릭 가능한 모든 요소에 `hover` + `focus-visible` 상태 제공
- 카드/버튼/본문 텍스트 대비 확보 (WCAG AA 지향)
- 로딩/빈 상태/오류 상태 UI 포함
- 첫 화면에서 핵심 CTA가 스크롤 없이 보이도록 구성

## 8) 구현 전/후 작업 규칙

- 구현 전:
  - 이 문서 + `PROJECT_ARCHITECTURE_CARD.md`만 읽고 시작
- 구현 후:
  - HOME 섹션 순서가 레퍼런스와 동일한지 확인
  - sketch 컨셉이 깨지는 스타일(글로우/과도한 둥근 모서리/약한 보더) 제거
