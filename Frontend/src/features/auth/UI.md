- 단순 참고가 아니라, 실제 서비스 코드로 바로 붙일 수 있는 수준의 LoginPanel 컴포넌트를 만든다.

[반드시 지켜야 할 구현 조건]
1. 기존 HTML의 레이아웃, 디자인 흐름, 카드형 구성, 버튼 구조를 최대한 유지할 것
2. 단순 HTML 복붙이 아니라 React/Next.js 구조에 맞게 정리할 것
3. 결과물은 LoginPanel 컴포넌트 전체 코드로 제공할 것
4. TypeScript 기준으로 작성할 것
5. 스타일은 Tailwind CSS 기준으로 작성할 것
6. 애니메이션은 Framer Motion을 사용하되, 과하지 않고 자연스럽게 구성할 것
7. 불필요하게 파일을 여러 개로 나누지 말고 우선 LoginPanel 하나로 완성할 것
8. 접근성 및 실사용성을 고려할 것

[로그인 UX 요구사항]
로그인 방식은 2개다.

A. 카카오 로그인
- “카카오 로그인” 버튼 클릭 시 카카오 로그인 URL로 이동
- 실제 인증 연동이 없어도 되며, 우선 이동 처리만 구현
- 카카오 로그인 URL은 추후 교체 가능하도록 상수 또는 props로 분리

B. 이메일 로그인
- “이메일 로그인” 클릭 시 이메일/비밀번호 입력 폼이 나타나야 한다
- 별도 페이지 이동보다, 기존 로그인 카드가 자연스럽게 전환되며 폼이 나타나는 UX를 우선 고려한다
- 즉, 같은 카드 영역 안에서 흐름이 이어지는 느낌으로 만들어라

[이메일 로그인 전환 인터랙션]
초기 상태:
- 카카오 로그인 버튼
- 이메일 로그인 버튼
- 원본 HTML에 있는 로그인 카드 UI 유지

이메일 로그인 클릭 시:
- 기존 선택 카드 또는 버튼 영역이 자연스럽게 사라지거나 슬라이드 아웃
- 같은 위치에 이메일/비밀번호 입력 폼이 fade + slide 형태로 등장
- 전환은 세련되고 부드러워야 하며, 서비스형 웹 UI에 맞아야 한다
- 과한 bounce, scale, flashy motion 금지

[이메일 로그인 폼 요구사항]
폼에는 최소 아래 요소가 있어야 한다.
- 이메일 입력 필드
- 비밀번호 입력 필드
- 로그인 버튼
- 이전 화면으로 돌아가는 버튼

그리고 아래도 고려할 것
- input focus 스타일
- 버튼 비활성화 상태
- 에러 메시지가 들어갈 공간 확보
- 향후 API 연결하기 쉬운 구조

[코드 작성 원칙]
- 바로 붙여넣어서 사용할 수 있는 완성형 코드로 작성
- 상태값은 명확하게 분리
  예: viewMode = 'default' | 'email'
- 이벤트 핸들러 명확히 작성
- mock 함수/임시 URL도 어디를 교체하면 되는지 분명히 보이게 작성
- 불필요한 추상화 금지
- 실무에서 리뷰 받아도 괜찮을 정도로 깔끔하게 작성
