# UX/UI 및 테마 참고

## 기본 컨셉

- Notion-like, Hand-drawn Sketch, Paper, Editorial, Korean fortune-telling mood
- 아이보리 종이 배경, 검은 보더, 오프셋 그림자, 작은 라운드를 유지한다.
- 과한 글로우, 네온, 유리질감, 강한 그라디언트는 피한다.
- 입력, 결제, 결과 화면은 명확성과 신뢰를 우선한다.

## 디자인 전수 시안 작업

- `Docs/01.페이지 설계/디자인 전수 변경`의 HTML 시안은 색상, 톤, 이미지, 카피 방향을 보존한다.
- 보라색 포인트, 밝은 배경, 히어로 이미지, 카드의 가벼운 그림자 톤을 다른 테마로 재해석하지 않는다.
- paper/sketch 토큰은 실제 프론트 구현 시 참고하되, 전수 시안 자체의 비주얼 아이덴티티를 강제로 바꾸지 않는다.
- UX/UI 수정 범위는 반응형 깨짐, 텍스트 겹침, 가로 스크롤, 터치 영역, focus/hover, 접근성 보강에 한정한다.
- 데스크탑에서 이미 의도된 3열 히어로 구도는 유지하되, 모바일에서는 같은 3열을 고집하지 않는다.

## 스타일 소스

- 색상, 반경, 그림자 변경은 컴포넌트 하드코딩보다 `src/app/globals.css`와 `tailwind.config.ts`를 먼저 확인한다.
- 기존 공용 클래스와 패턴을 우선 사용한다: `page-shell`, `page-grid`, `hero-panel`, `btn-saju-*`, `card-saju-primary`, `sketch-border`, `sketch-highlight`, `sketch-input`.
- 공용 버튼은 `src/shared/ui/button.tsx`의 `Button` 변형을 먼저 검토한다.

## 레이아웃 규칙

- 모바일 우선으로 구성하되 데스크탑에서는 정보 구조가 자연스럽게 확장되도록 한다.
- 버튼과 입력의 최소 터치 영역은 40px 이상을 지향한다.
- 클릭 가능한 요소에는 `hover`와 `focus-visible` 상태를 제공한다.
- 텍스트 대비는 WCAG AA 수준을 지향한다.
- 로딩, 빈 상태, 오류 상태 UI를 함께 고려한다.
- 고정 폭/고정 컬럼을 사용할 때는 모바일 breakpoint에서 반드시 단일 컬럼 또는 축약 UI로 전환한다.
- 화면 밖으로 카드가 걸쳐 보이는 구성은 의도된 캐러셀/스크롤 영역이 아니면 사용하지 않는다.
- 장식 이미지는 텍스트와 CTA를 덮지 않아야 하며, 모바일에서는 이미지 위치와 opacity를 별도로 조정한다.

## 웹앱 해상도 기준

- 기준 모바일 폭은 390px로 잡고, 최소 360px까지 깨지지 않게 구성한다.
- 태블릿 기준 폭은 768px로 본다.
- 데스크탑 시작 기준은 1024px, 기본 작업 폭은 1280px로 본다.
- 본문 컨테이너는 `max-width`를 두어 초광폭 화면에서 가독성을 유지한다(기본 1200px 권장).
- 모바일에서 가로 스크롤이 발생하지 않도록 구성한다.
- 버튼/입력 등 터치 요소의 최소 높이는 44px 이상을 권장한다.

## QA 뷰포트 체크

- 필수 확인 뷰포트: 360 / 390 / 768 / 1024 / 1280
- 체크 항목: 텍스트 잘림 없음, 버튼/입력 겹침 없음, 가로 스크롤 없음, 주요 액션 접근 가능
- 홈 히어로는 로그인/비로그인 상태를 모두 확인한다.
- 모바일 QA에서는 첫 화면 CTA, 로그인 버튼, 요약 카드 또는 로그인 유도 카드가 화면 밖으로 밀리지 않는지 확인한다.

## 테마 변경 작업

- 기존 UX 구조를 유지해야 하는 테마 변경 작업에서는 배치, 간격, 정렬을 바꾸지 않는다.
- 시각 요소만 변경한다: 배경색, 테두리, 폰트, 아이콘, 그래픽 요소.
- 같은 의미의 색상이나 그림자 값을 여러 파일에 복붙하지 않는다.
- 사용자가 색상/톤 유지를 지시한 경우 테마 변경을 하지 않는다. 이때는 레이아웃 안정화와 상태/접근성 개선만 수행한다.
