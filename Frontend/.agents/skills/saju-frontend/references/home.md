# /home 작업 참고

## 읽는 조건

`/`, `/home`, HOME 화면, 홈 운세 데이터, 추천 서비스, 바로가기 카드 UI를 수정할 때 읽는다.

## 관련 경로

- `apps/web/src/app/(main)/home`
- `apps/web/src/features/home`
- `apps/web/src/widgets/homeSection`
- `apps/web/src/widgets/welcom-section`
- 디자인 전수 시안: `Docs/01.페이지 설계/디자인 전수 변경/home-design.html`
- 디자인 전수 시안(비로그인): `Docs/01.페이지 설계/디자인 전수 변경/home-design-guest.html`

## 정보 구조

- 상단 헤더 영역
- 메인 배너 또는 히어로 영역
- 빠른 진입 메뉴
- 추천 또는 프로모션 카드 영역
- 카테고리별 서비스 리스트 블록
- 모바일 하단 네비게이션이 필요한 경우 별도 검토

## 작업 규칙

- 점신 레퍼런스의 콘텐츠 순서와 정보 위계를 참고한다.
- 모바일 앱 프레임을 데스크탑 웹에 그대로 복제하지 않는다.
- 데스크탑에서는 글로벌 헤더와 메인 컨테이너 중심의 웹서비스 레이아웃을 유지한다.
- 모바일에서는 단일 컬럼으로 자연스럽게 접히게 한다.
- 기존 sketch 토큰과 공용 카드/버튼 패턴을 우선 사용한다.
- 홈 데이터 조회와 상태 로직은 `features/home/hooks` 쪽으로 분리한다.
- 홈의 추천/프로모션 CTA가 사주 기본정보 의존 서비스로 연결되면 `/saju` 온보딩 흐름과 진입 정책을 맞춘다. 보호 서비스는 `/saju?next=...&forceInput=1`로 통일한다.
- `정통사주`, `궁합`, `오늘의 메뉴`, `커뮤니티`처럼 보호 서비스 CTA는 홈 카드 링크와 실제 라우트 가드 정책이 서로 어긋나지 않게 유지한다.
- 홈 `나의 오행 분석` 카드처럼 결과 조회 API를 직접 호출하는 영역에서는 `PENDING_FORM_NOT_FOUND` 같은 백엔드 에러 코드를 사용자 문구로 매핑한다. raw 영어 메시지를 그대로 노출하지 않는다.
- 전역 헤더의 `ME` 표시는 토큰 쿠키 기반 분기일 수 있다. 로그아웃 UX나 인증 표시 문제를 볼 때는 디자인 문제와 인증 판정 문제를 분리해서 확인한다.

## 디자인 전수 HTML 수정 규칙

- `home-design.html`과 `home-design-guest.html`은 같은 레이아웃 규칙을 공유해야 한다.
- 현재 시안의 색상, 보라색 포인트, 밝은 히어로 톤, 이미지, 카피 방향은 유지한다.
- UX/UI 수정은 모바일 대응, 겹침 제거, 가로 오버플로우 제거, 접근성 보강을 우선한다.
- 데스크탑 히어로의 좌측 카피, 중앙 이미지, 우측 카드 구도는 유지한다.
- 모바일에서는 데스크탑 3열 그리드를 유지하지 말고 텍스트, CTA, 이미지, 카드가 세로 흐름으로 읽히게 한다.
- 우측 명식 요약 카드와 비로그인 로그인 유도 카드는 모바일에서 화면 밖으로 밀리면 안 된다.
- 모바일 내비게이션은 로고와 핵심 액션만 남기고, 메뉴 목록은 숨기거나 별도 메뉴로 축약한다.
- 히어로 배경 이미지는 모바일에서 텍스트 가독성을 해치지 않도록 크기, 위치, 레이어, 투명도를 별도 조정한다.
- CTA와 로그인 버튼은 최소 높이 44px 이상을 유지하고 `focus-visible` 상태를 제공한다.
- 프로필 아바타, 알림, 로그인 버튼처럼 클릭 가능한 요소는 실제 버튼 semantics 또는 접근 가능한 이름을 가져야 한다.

## 체크리스트

- 첫 화면에서 핵심 CTA가 보이는지 확인한다.
- 텍스트 겹침과 버튼 터치 영역 문제를 확인한다.
- 레퍼런스 구조를 따르되 카피와 데이터는 우리 서비스 맥락으로 치환한다.
- 로그인/비로그인뿐 아니라 "로그인했지만 사주 기본정보 없음" 상태에서 각 CTA가 어느 경로로 가는지 확인한다.
- 홈 카드에서 API 오류가 날 때 사용자 문구와 CTA가 서비스 의도에 맞게 바뀌는지 확인한다.
- 360px와 390px에서 가로 스크롤이 없어야 한다.
- 768px에서 태블릿 레이아웃이 데스크탑 3열과 모바일 단일 컬럼 사이에서 어색하게 끼지 않아야 한다.
- 로그인/비로그인 두 HTML의 히어로 높이, 간격, CTA 위치가 서로 크게 어긋나지 않아야 한다.

## 관계 규칙

- `HomePage`는 서비스 진입 허브이며 각 CTA는 실제 라우트 가드 정책과 연결된다.
- `ProtectedServiceCta`는 사주 기본정보가 필요한 경우 `/saju?next=...&forceInput=1`로 연결된다.
- `HomeDesignPrototype`은 로그인/비로그인 HTML이 같은 레이아웃 규칙을 공유한다.
- `HomeApiCard`는 API 오류 코드를 사용자 문구와 CTA로 매핑해야 한다.
- 전역 헤더의 인증 표시는 토큰 쿠키 존재와 실제 인증 성공을 구분해서 판단한다.

## 불변조건

- 홈 CTA와 대상 라우트의 보호 정책이 서로 어긋나지 않아야 한다.
- API 오류의 raw 영어 메시지를 홈 카드에 직접 노출하지 않는다.
- 모바일에서 가로 스크롤과 텍스트/카드 겹침이 없어야 한다.
- 로그인/비로그인 HTML은 같은 정보 위계와 레이아웃 원칙을 유지한다.
- 클릭 가능한 요소는 접근 가능한 이름과 적절한 semantics를 가져야 한다.

## 명령 해석 규칙

- “홈”, “메인”, “랜딩” 요청은 `features/home`, `widgets/homeSection`, `widgets/welcom-section`을 우선 확인한다.
- “홈 CTA 경로” 요청은 대상 서비스의 보호 정책과 `/saju` 온보딩 흐름을 함께 확인한다.
- “홈 디자인 전수 HTML” 요청은 `home-design.html`과 `home-design-guest.html`을 같은 규칙으로 비교한다.
- “ME 표시/로그아웃 표시” 요청은 디자인보다 쿠키 기반 분기와 실제 인증 판정을 먼저 분리한다.
