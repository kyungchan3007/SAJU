# Frontend SEO 적용 정리

## 문서 목적

이 문서는 현재 `Frontend` 프로젝트에 반영한 SEO 작업이 어떤 기준으로 들어갔는지, 왜 그렇게 했는지, 그리고 배포 후 어떤 결과를 기대할 수 있는지를 정리하기 위한 문서다.

이 문서는 "현재 코드 기준 설명 문서"다. 실제 성과 수치는 아직 측정 전이므로, 아래 수치 예측은 가정 기반 추정치로 봐야 한다.

## 이번 SEO 작업의 범위

현재 SEO 작업은 홈 화면 기준으로 반영했다.

- 공통 메타데이터 정리
- 홈 페이지 전용 메타데이터 분리
- `WelcomeSection` 시맨틱 태그 정리
- 홈 화면의 제목, 설명, CTA 문구를 검색엔진이 이해하기 쉬운 구조로 수정
- JSON-LD 구조화 데이터 추가

## 적용 파일

- `src/app/layout.tsx`
- `src/app/page.tsx`
- `src/shared/config/env.ts`
- `.env.example`
- `src/widgets/welcom-section/ui/welcom-section.tsx`
- `src/widgets/welcom-section/ui/title/title.tsx`
- `src/widgets/welcom-section/ui/button/cta-button.tsx`

## 어떤 기준으로 SEO를 적용했는가

이번 작업은 아래 기준으로 적용했다.

### 1. Next.js App Router 권장 방식

App Router에서는 `head` 태그를 직접 조작하기보다 `metadata` API를 활용하는 것이 기본 방식이다.

그래서 다음처럼 역할을 분리했다.

- `layout.tsx`: 사이트 공통 SEO 기본값
- `page.tsx`: 홈 페이지 전용 SEO
- UI 컴포넌트: 실제 본문 구조와 시맨틱 태그

이 구조는 유지보수와 페이지 확장에 유리하다. 이후 `/saju`, `/compatibility`, `/location` 같은 페이지도 같은 방식으로 확장할 수 있다.

### 2. 검색엔진은 메타데이터와 본문을 같이 본다는 기준

SEO는 메타 태그만 넣는다고 끝나지 않는다. 검색엔진은 다음을 같이 읽는다.

- 페이지 제목
- 메타 설명
- 실제 본문의 `h1`
- 문단 설명
- 링크 텍스트
- 시맨틱 태그 구조

그래서 메타데이터와 본문이 같은 주제를 말하도록 정리했다.

예를 들면 아래 흐름이다.

- 메타 제목: 무료 사주 풀이와 궁합 확인
- 본문 `h1`: 별이 말하는 당신의 사주 이야기
- 설명 문단: 사주팔자, 궁합, 오늘의 흐름
- CTA 링크: 무료 사주 보기, 무료 궁합 확인

즉, "사주/궁합/운세"라는 핵심 주제를 메타와 본문이 함께 지지하도록 맞췄다.

### 3. 시맨틱 HTML 우선 기준

현재 홈 화면은 디자인 위주 구성에서 SEO 친화적인 문서 구조로 조금 더 정리했다.

적용 기준은 아래와 같다.

- 페이지 핵심 콘텐츠는 `main` 안에 둔다
- 대표 히어로 구역은 `section`으로 감싼다
- 대표 제목은 `h1`로 둔다
- 소개성 문구는 `header`와 `p`로 구조화한다
- 주요 이동 링크는 `nav`로 묶는다
- 장식 요소는 `aria-hidden` 처리한다

이 기준은 검색엔진뿐 아니라 접근성 측면에서도 기본적으로 맞는 방향이다.

### 4. 링크 텍스트는 목적이 분명해야 한다는 기준

아래처럼 추상적인 텍스트는 검색엔진 문맥이 약하다.

- 시작하기
- 더보기
- 바로가기

그래서 CTA를 아래처럼 바꿨다.

- 무료 사주 보기
- 무료 궁합 확인

이렇게 하면 검색엔진이 링크 목적을 더 잘 이해할 수 있고, 사용자도 더 빠르게 내용을 파악할 수 있다.

### 5. URL 정규화 기준

공통 메타에서 아래 요소를 정리했다.

- `metadataBase`
- `canonical`
- `robots`
- `openGraph`
- `twitter`

이 작업은 검색엔진과 소셜 공유 시 URL과 제목/설명이 일관되게 보이도록 하기 위한 기본 세팅이다.

### 6. 구조화 데이터 기준

홈 페이지에는 JSON-LD 형태의 `WebPage` 구조화 데이터를 추가했다.

이유는 다음과 같다.

- 검색엔진이 이 페이지를 단순 HTML이 아니라 명확한 "웹페이지 개체"로 이해하게 돕기 위해
- 향후 `WebSite`, `FAQPage`, `Service` 등으로 확장하기 쉽게 만들기 위해

현재는 최소 수준의 구조화 데이터만 넣었다.

## 왜 이 작업을 했는가

이번 작업의 목적은 단순히 메타 태그를 채우는 것이 아니라, 홈 화면의 주제를 검색엔진이 더 명확하게 해석할 수 있도록 만드는 것이다.

기존 상태에서 예상 가능한 문제는 아래와 같았다.

- 공통 메타만 있으면 페이지별 제목과 설명이 분리되지 않음
- 본문이 감성 카피 중심이면 검색 키워드 문맥이 약함
- CTA가 추상적이면 페이지 목적 전달력이 낮음
- 시맨틱 구조가 약하면 검색엔진이 문서 계층을 이해하기 어려움

이번 작업으로 해결하려고 한 것은 아래다.

- 홈 페이지가 사주/궁합/운세 관련 페이지라는 점을 더 명확하게 전달
- 홈 페이지 제목과 설명을 별도로 관리
- 검색엔진과 소셜 공유 모두에서 일관된 제목/설명 사용
- 향후 페이지별 SEO 확장 구조 마련

## 기대 효과

이번 변경은 "검색 순위가 갑자기 크게 오른다"는 성격보다는, 검색엔진이 페이지를 해석하는 품질을 올리는 기반 작업에 가깝다.

예상되는 효과는 아래와 같다.

### 1. 검색엔진 해석 정확도 개선

홈 페이지가 어떤 주제의 페이지인지 더 명확하게 전달된다.

예상 효과:

- 브랜드 키워드 검색 시 제목/설명 일관성 향상
- 사주/궁합 관련 롱테일 키워드와의 문맥 정합성 개선
- 크롤러가 홈 페이지를 대표 페이지로 이해하기 쉬워짐

### 2. 검색 결과 클릭률 개선 가능성

검색 순위가 그대로여도, 제목과 설명이 더 명확해지면 CTR이 좋아질 수 있다.

예상 범위:

- 브랜드 키워드 CTR: 기존 대비 `+5% ~ +20%`
- 비브랜드 롱테일 CTR: 기존 대비 `+3% ~ +12%`

주의:

이 수치는 배포 후 실제 검색 노출이 발생하고, 제목/설명 문구가 검색 결과에 그대로 반영된다는 전제에서만 의미가 있다.

### 3. 소셜 공유 품질 개선

Open Graph와 Twitter 메타가 정리되어 있으면 링크 공유 시 제목/설명이 더 안정적으로 출력된다.

예상 효과:

- 카카오톡, 디스코드, 슬랙 등 링크 공유 시 미리보기 일관성 개선
- 공유 링크 클릭률 `+5% ~ +15%` 가능성

단, 이 효과는 실제 `og-image` 파일과 배포 도메인이 올바르게 연결된 경우에 한한다.

### 4. 색인 안정성 개선

canonical, metadataBase, robots가 정리되면 색인 기준이 더 선명해진다.

예상 효과:

- 중복 URL 해석 문제 감소
- 대표 URL 판단 안정성 증가
- 크롤링 시 기본 문서 해석 품질 향상

이 부분은 체감형 성과보다 기술적 안정성에 가까운 효과다.

## 예상 수치

아래 수치는 현재 작업 범위만 기준으로 한 보수적 추정치다.

### 단기 예상: 배포 후 2주 ~ 4주

- 검색 노출수: `0% ~ +10%`
- 검색 CTR: `+3% ~ +15%`
- 브랜드 검색 클릭률: `+5% ~ +20%`
- 페이지 체류 관련 간접 지표: 변화 미미하거나 `0% ~ +5%`

설명:

이번 작업은 기술 SEO와 문맥 정리 중심이다. 콘텐츠 양 자체를 늘린 작업은 아니므로, 노출수보다 CTR 쪽 개선 가능성이 더 높다.

### 중기 예상: 1개월 ~ 3개월

추가 조건이 충족되면 아래 정도를 기대할 수 있다.

조건:

- 실제 배포 도메인 연결
- `og-image` 준비
- `/saju`, `/compatibility` 페이지별 SEO 분리
- Search Console 등록
- sitemap, robots.txt 점검
- 지속적인 콘텐츠 확장

예상 범위:

- 비브랜드 롱테일 노출수: `+10% ~ +35%`
- 홈 페이지 CTR: `+5% ~ +18%`
- 페이지 인덱싱 안정성: 정성적으로 개선 가능성 높음

## 아직 남아 있는 리스크와 미완료 항목

현재 구현은 "기반 작업" 수준이며, 아래 항목이 남아 있다.

### 1. 실제 도메인 값 미확정 가능성

`NEXT_PUBLIC_APP_URL`은 실제 배포 도메인으로 확정해야 한다.

이 값이 잘못되면:

- canonical 오류 가능성
- Open Graph URL 오류 가능성
- 구조화 데이터 URL 오류 가능성

### 2. `og-image.png` 부재

현재 코드에서는 `/og-image.png`를 참조한다. 하지만 현재 `public` 폴더 기준으로 이 파일은 아직 없는 상태다.

영향:

- 소셜 공유 미리보기 품질 저하
- Open Graph 이미지가 비어 있거나 fallback 처리될 수 있음

### 3. 페이지별 SEO 확장 미완료

현재는 홈 기준 작업만 정리된 상태다.

추후 아래 페이지도 분리하는 것이 좋다.

- `/saju`
- `/compatibility`
- `/location`
- 로그인 관련 페이지

### 4. 검색 콘솔/분석 도구 연결 전

아직 실제 성과를 검증하려면 아래 도구 연결이 필요하다.

- Google Search Console
- Google Analytics 또는 대체 분석 도구
- Bing Webmaster Tools

## 다음 단계 제안

우선순위 기준 추천 순서는 아래와 같다.

1. `NEXT_PUBLIC_APP_URL`을 실제 배포 도메인으로 반영
2. `public/og-image.png` 제작 및 연결
3. `/saju`, `/compatibility` 페이지별 `metadata` 추가
4. sitemap, robots.txt 점검
5. Search Console 등록
6. 검색 유입 키워드 측정 후 제목/설명 A/B 조정

## 요약

현재 SEO 작업은 "홈 페이지를 검색엔진이 이해하기 쉬운 형태로 재정리한 1차 기반 작업"이다.

핵심은 아래 세 가지다.

- 메타데이터를 공통/페이지 단위로 나눴다
- `WelcomeSection` 본문 구조를 시맨틱하게 정리했다
- 검색엔진과 공유 시스템이 읽는 문맥을 일관되게 맞췄다

예상 효과는 즉시 순위 상승보다는, 아래에 더 가깝다.

- 검색엔진 해석 품질 개선
- 검색 결과 CTR 개선 가능성
- 링크 공유 품질 개선
- 이후 페이지 SEO 확장 기반 확보

실제 수치를 만들려면 배포 이후 Search Console과 분석 도구 기준으로 검증해야 한다.
